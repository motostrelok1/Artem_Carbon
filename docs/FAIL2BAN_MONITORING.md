# PR #70 — Fail2ban (SSH) и мониторинг Artem Carbon

**Этап:** отдельный PR. Не изменяет работающий Nginx, SSH, UFW или сетевые правила автоматически при merge/deploy. Установка и включение Fail2ban — отдельное действие оператора через консоль VDS.

## Основание
22.11.2026 проверено: активный Nginx anti-flood отвечает HTTP 200 на обычные запросы и HTTP 429 на короткий всплеск из 30 параллельных запросов (21×200, 9×429). Это не подтверждает устойчивость к сетевому DDoS и не означает, что банить за 429 безопасно.

## Что добавлено
- `config/fail2ban/jail.d/artemcarbon-sshd.local` — **только SSH**: 5 неудачных попыток за 10 минут, блокировка на 1 час, журнал systemd; `ignoreip` только loopback. Доверенный удалённый IP не добавлен: его необходимо согласовать и проверить до включения.
- `scripts/security-status.sh` — **только чтение**: состояние сервисов, загрузка, память, диск, количество HTTP 429/5xx и состояний anti-flood по последним 1000 строкам; SSH jail — только счётчики. IP посетителей не печатает. Для доступа к логам запустить через `sudo`.
- `tests/test_security_monitoring.py` и CI — защита от случайного добавления HTTP-ban jail и проверка синтаксиса.

**Не добавляем Nginx fail2ban jail для HTTP 429.** Легитимные пользователи за NAT/мобильными операторами могут иметь общий IP и случайно превысить rate-limit. Админский вход также не блокируем на уровне IP по ответам 401/429 без отдельного анализа и тестов.

## Перед установкой на Ubuntu VDS

1. Держать открытой отдельную действующую SSH-сессию и проверить доступ к аварийной консоли провайдера (VNC/serial). Не закрывать её до проверки новых SSH-подключений.
2. Выяснить фактический SSH порт (`sudo sshd -T | grep '^port '`), используемый firewall (`sudo ufw status verbose`, `sudo nft list ruleset`) и уже существующие правила Fail2ban (`sudo fail2ban-client status`, если установлен).
3. Если SSH не на порту 22 — **сначала исправить `port = ssh`** на фактический порт.
4. При доступе через известный статический доверенный IP аккуратно добавить его в `ignoreip` с пониманием рисков; не добавлять публичные или неизвестные подсети.
5. Проверить, что `sshd` виден в `journalctl -u ssh --since '1 hour ago'`. На Ubuntu журнал может называться по-другому, это следует уточнить.

## Ручная установка (не из deploy)

После всех проверок:

```bash
sudo apt-get update
sudo apt-get install -y fail2ban
sudo install -o root -g root -m 0644 \
  /opt/artems-carbon/repo/config/fail2ban/jail.d/artemcarbon-sshd.local \
  /etc/fail2ban/jail.d/artemcarbon-sshd.local
sudo fail2ban-client -t
sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd
```

Перед включением надо ознакомиться с другими `/etc/fail2ban/jail.d/` и `jail.local`: на сервере могли быть уже включены другие правила. Команды установки не должны перезаписывать их. Установка пакета может стартовать службу автоматически, поэтому **предварительно** проверить доступ через аварийную консоль.

Проверить вход **новым** SSH-сеансом, не закрывая старый. Не проводить искусственный подбор паролей и не банить собственный IP для теста.

## Мониторинг

```bash
sudo bash /opt/artems-carbon/repo/scripts/security-status.sh
sudo fail2ban-client status sshd
sudo journalctl -u fail2ban --since '1 hour ago' --no-pager
```

Результат `security-status.sh` — агрегаты. Не публиковать сырые строки журналов с IP покупателей. Для более долгосрочных графиков/уведомлений понадобится отдельная согласованная система мониторинга.

## Откат SSH jail (если возникла проблема)

Если доступ к SSH заблокирован, использовать **консоль провайдера**:

```bash
sudo systemctl stop fail2ban
sudo mv /etc/fail2ban/jail.d/artemcarbon-sshd.local \
  /etc/fail2ban/jail.d/artemcarbon-sshd.local.disabled
sudo fail2ban-client -t
```

Команда остановки службы может не удалить правила блокировки в отдельных сетевых конфигурациях. Через консоль провайдера проверить фактические правила firewall и восстановить доступ, не сбрасывая все защитные правила без диагностики. Для повторного включения сначала исправить порт, `ignoreip` или конфликтующую конфигурацию.

**Важно:** изменения в этом PR сами по себе Fail2ban на VDS не устанавливают и не активируют. Конфигурация подготовлена для контролируемого ручного этапа. Внешняя защита от сетевого DDoS (до VDS) остаётся отдельной задачей.

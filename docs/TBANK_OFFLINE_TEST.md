# Изолированное тестирование оплаты Т-Банка

## Назначение
Этот режим тестирует **код интеграции**, а не настоящий процессинг Т-Банка. Не используется рабочий терминал, не проводится платеж на 1 ₽, не требуется фискализация, не расходуются номера из рабочей базы `artems_carbon`.

## Что запускается в CI
- Временная база `artems_carbon_ci` в контейнере PostgreSQL 16.
- Миграции `001`–`005` в эту временную базу.
- Локальная имитация только метода Т-Банка `/v2/Init` на `127.0.0.1`, с **фиктивными** `TerminalKey/Password`.
- Отдельный процесс настоящего API `src/app.js` на локальном порту с `PAYMENTS_ENABLED=true` **только в CI-процессе**.
- Настоящий путь `POST /api/orders` с ФИО, email, телефоном и двумя согласиями, цены вычисляются сервером.
- Проверка формирования запроса Init: сумма, подпись, налоговые параметры и URL уведомления.
- Проверка отклонения уведомления с подменённой суммой/неверной подписью.
- Имитация корректного подписанного `CONFIRMED`: статус `paid`, два разных номера от 1 до 9500, очередь одного письма.
- Повтор того же `CONFIRMED`: нет дублированных номеров, писем и событий.
- Формирование письма с действительными присвоенными номерами, **без SMTP-отправки**.
- Имитация подписанного `REFUNDED`: номера помечены аннулированными, публичный счётчик уменьшился до нуля.

Тест вызывается вместе с `npm test` в GitHub Actions и автоматически пропускается на VDS, когда переменная `TEST_DATABASE_URL` не определена. Для него **не надо** добавлять `TEST_DATABASE_URL` в рабочий `.env`.

## Важное разграничение
- **CI PASS** означает, что собственные бизнес-правила проходят изолированный сценарий с поддельным банком, **не** что Т-Банк принял запросы.
- Реальный Т-Банк, платёжная страница, 1 ₽, callbacks из интернета, кассовый чек и доставка SMTP не проверяются этим набором.
- Рабочий `PAYMENTS_ENABLED=false` не менять и настоящий терминал сейчас не трогать.
- До боевого запуска необходимы согласование правового сценария передачи автомобиля, фискализация, ограничение доступного остатка 9500 при одновременных платежах, частичные возвраты, защита API и публикация политики персональных данных.
- Пароли рабочего терминала остаются только на VDS. В GitHub Actions используются исключительно фиктивные значения.

## Локальный запуск (только на отдельной тестовой БД)
Тест требует выделенную пустую PostgreSQL 16 с пользователем, имеющим право создавать роль `artems_app` для применения миграции 004. Укажите **только адрес тестовой БД** в переменной `TEST_DATABASE_URL`, например для локального CI-аналога, и затем запустите `cd server && npm test`. Нельзя направлять `TEST_DATABASE_URL` на `artems_carbon`: тест добавляет заказы и номера.

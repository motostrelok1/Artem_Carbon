# Согласия при оформлении видеоурока

В форме покупки два чекбокса, по умолчанию оба **выключены**:

1. **«Согласен с предоставлением персональных данных»**. Текст является ссылкой на отдельную страницу `privacy.html`, открываемую в новой вкладке. Она стилизована под главный экран и содержит контейнер с заглушкой для будущей политики сбора, обработки и хранения персональных данных.
2. **«Согласен на получение информационных электронных писем о ходе мероприятия и его результатах (в том числе о том, стал ли я обладателем автомобиля)»**.

По текущему требованию владельца сайта **обе галочки обязательны** для активации кнопки перехода к оплате. При прямом обращении к API оба поля `buyer.personalConsent` и `buyer.marketingConsent` проверяются на строгое `true`, без них заказ не создаётся.

В базе `orders` фиксируются `personal_data_consent_at`, `marketing_email_consent_at` и `consent_policy_version` (`draft-2026-11`). Текст документа пока отсутствует: это **временный макет**, а не окончательная опубликованная политика. До сбора реальных персональных данных требуется разместить утверждённый текст и зафиксировать его актуальную версию; юридическая оценка обязательности согласия на рассылку этим PR не проводилась.

## Обновление VDS

После слияния PR обновить код `git pull --ff-only`, применить `server/sql/005_checkout_consents.sql` к `artems_carbon`, запустить `npm test`, затем перезапустить `artems-carbon.service`. Платежи остаются отключёнными до отдельного решения.

# Согласия при оформлении видеоурока

В форме покупки два независимых чекбокса, оба по умолчанию **выключены**:

1. **Обработка персональных данных** — требуется подтверждение перед оформлением заказа. Ссылка ведёт на `privacy.html`.
2. **Рассылка новостей проекта и сообщений о мероприятии** — отдельное **добровольное** согласие. Его отказ не блокирует покупку и не отменяет необходимые уведомления о заказе.

На стороне сервера `buyer.personalConsent` должен быть строго `true`. `buyer.marketingConsent` допускает `true`, `false` или отсутствие поля; значения другого типа отклоняются. Сервер сохраняет `marketing_email_consent_at` только при явном `true`; при отказе хранит `NULL`. `personal_data_consent_at` фиксируется после обязательного подтверждения.

**До запуска продаж:** `privacy.html` пока содержит заглушку, а `consent_policy_version` установлен в `draft-2026-11`. Нужно заменить заглушку согласованной политикой, указать реквизиты оператора, состав и цели обработки, сведения об отзывах согласий и реальную версию документов. Также требуются оферта, правила мероприятия и условия возврата. Эта техническая доработка не означает юридического согласования документов.

## Проверки

- Без обязательного согласия кнопка продолжения неактивна, сервер отклоняет заказ.
- С обязательным согласием и **без** рассылки продолжение доступно, заказ создаётся в разрешённой тестовой среде; `marketing_email_consent_at IS NULL`.
- При добровольном согласии на рассылку сохраняется дата согласия.
- Строки вместо булевых значений не засчитываются как согласие.
- Подтверждение оплаты, письмо с номером и выдача оплаченного урока не зависят от маркетинговой галочки.

Реальные платежи остаются отключёнными до отдельного решения по фискализации и юридическим документам.

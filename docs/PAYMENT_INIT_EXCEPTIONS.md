# Неопределённый результат создания платежа T-Банк /Init

## Зачем
На этапе `POST /api/orders` сервер сначала бронирует номера, затем вызывает банк `/Init`.
Если ответ потерян, банк **мог создать** платёж. Поэтому ошибка 503 **не означает подтверждённую отмену** и не даёт права автоматически освободить номера.

## Поведение

1. При ошибке `Init` (либо при ошибке сохранения `PaymentId`) сервер возвращает `503` и `orderId`, не освобождает резерв и не списывает средства.
2. Покупатель видит код заказа и предложение обратиться к поддержке, не повторяя попытку до проверки.
3. В админке появляется «Нужна сверка с банком» для `pending`-заказов без `PaymentId`, возраст которых более 2 минут. Список заказов выделяет эти записи.
4. Таймер `artems-carbon-reconcile.timer` **не трогает** такие записи: он обслуживает только известные `PaymentId` и только при подтверждённом финальном статусе банка.
5. Администратор сверяет `OrderId`, сумму и терминал с банковским кабинетом/поддержкой. Нельзя освобождать номер, пока банк не подтвердил, что плательщик не сможет завершить оплату. При подтверждённом платеже требуется ручное завершение заказа и выдачи, а не новая автоматическая бронь.

## Ограничения

- Это **индикация для ручной сверки**, а не автоматический запрос в банк по `OrderId`. Банковский механизм поиска не подтверждён, безопасная автоматическая отмена не реализована.
- Метрика считает все давние `pending` без `PaymentId`: причины могут включать потерю банковского ответа и сбой записи в БД.
- Админка требует серверной авторизации. В логи не записываются реквизиты карты и банковские секреты.
- `PAYMENTS_ENABLED=false` остаётся неизменным; без фискализации и юридических документов продажи не включать.

# Защищённая выдача видеоурока после оплаты

## Что реализовано

После подтверждения оплаты `CONFIRMED` штатный обработчик почты добавляет в письмо покупателю защищённую ссылку на видеоурок **только если** на VDS установлен настоящий видеофайл, задан сильный `LESSON_ACCESS_SECRET` и `API_PUBLIC_URL` работает по HTTPS.

При отсутствии файла/секрета основной процесс покупки, назначения номеров и письма **не меняется**: покупателю уходит прежнее письмо с номерами без неработающей видеоссылки.

- Письмо содержит отдельные номера покупки и кнопку «Смотреть приобретённый видеоурок».
- Подписанная HMAC-ссылка индивидуальна для заказа; её секрет в **фрагменте URL** (`#token=...`), который не отправляется серверу в HTTP GET и не попадает в обычные access-логи Nginx.
- Браузер обменивает ссылку на HttpOnly/Secure/SameSite=Strict cookie (на 8 часов), после чего воспроизводит видео без токена в URL.
- Каждый запрос на просмотр видео сверяет статус `paid` и покупку `video_lesson` с PostgreSQL. После полного `REFUNDED` или отмены оплаченный доступ прекращается.
- Видео сервер выдаёт с поддержкой `Range` (`206 Partial Content`), перемотки и ответом `416` на недопустимый диапазон.
- Файл хранится **вне публичного сайта**; в GitHub, `/opt/artems-carbon/site` и Nginx public root его публиковать нельзя.
- Статус готовности находится в авторизованном `GET /api/admin/system`: `lessonDeliveryReady`.

## Чего пока нет

**В репозитории нет самого видеоурока.** Его должен предоставить правообладатель. Поэтому готовую выдачу пока нельзя считать включённой или проверенной реальным просмотром.

Ссылка — секретный ключ доступа, которым владеет получатель письма. Получатель может переслать её другому человеку; это **не DRM** и не защита от записи экрана. Для более жёсткого контроля в будущем можно добавить личный кабинет, водяной знак и повторную авторизацию.

## Подготовка файла на VDS

После согласования и проверки прав на видео разместить MP4 (H.264/AAC, `moov` в начале файла для быстрой перемотки) по пути:

`/opt/artems-carbon/private-media/lesson.mp4`

Каталог создаёт `scripts/deploy-full-vds.sh`, владелец `root`, группа `artems-carbon`, права `0750`. Файл должен иметь владельца `root`, группу `artems-carbon`, права `0640`; не помещать его в `/site` и не коммитить в GitHub. При загрузке убедиться, что файл открывается и соответствует продаваемому уроку. Без настоящего видео включать ссылки нельзя.

В приватном `/opt/artems-carbon/server/.env` задать уникальный секрет длиной не менее 32 символов (`LESSON_ACCESS_SECRET`, рекомендуем 64 случайных hex-символа). Для генерации использовать `openssl rand -hex 32`; не размещать значение в истории команд, GitHub или чате. `LESSON_VIDEO_PATH` можно не указывать: путь по умолчанию указан выше. `API_PUBLIC_URL` должен быть `https://api.artemcarbon.ru`.

После настройки перезапустить API `artems-carbon`; штатный таймер `artems-carbon-mail.timer` автоматически считывает новые переменные при следующем запуске worker. **Не менять `PAYMENTS_ENABLED` ради проверки видео.** Секрет не менять без плана миграции: существующие ссылки перестанут работать.

## Проверки до допуска покупателей

1. `npm test` — тесты подписи, сессии, диапазонов, email-шаблона.
2. В админском `/api/admin/system` проверить `lessonDeliveryReady=true` без публикации значений секретов.
3. В изолированной тестовой БД создать тестовый заказ `paid` с одним видеоуроком, пройти письмо и открытие ссылки на тестовом адресе; после теста удалить записи и восстановить свободные номера.
4. Проверить перемотку и `206`, попытку открытия без cookie, чужой заказ/поддельный токен, прекращение доступа после `REFUNDED`.
5. Убедиться, что видео напрямую по URL `/site` или публичному статическому пути недоступно.
6. Только после юридической/фискальной готовности и контрольного платежа разрешать реальную оплату.

## Отдельные ограничения перед публичными продажами

Фискализация, правила акции с автомобилем, оферта, ПДн, возвраты и юридическое согласование остаются вне этого PR. Настройка защищённого видео **не** включает онлайн-кассу или платежи.

# Artem Carbon — CloudKassir + Т-Банк: фискализация до запуска

**Статус: подключение кассы и проверка реального чека ещё не подтверждены. Реальные продажи должны оставаться выключенными.** Документ описывает выбранную архитектуру и ручные шаги в кабинетах поставщиков; он не является подтверждением выполнения регистрации ККТ в ФНС или юридической экспертизой.

## Архитектура

- Самописный сайт `artemcarbon.ru` → Node.js API `/api/orders` → интернет-эквайринг **Т-Банк** `/v2/Init`.
- В `/v2/Init` API уже передаёт `Receipt`: `Email`, `Taxation`, `Items[0]` с `Name`, `Quantity`, `Price`, `Amount`, `Tax`, `PaymentMethod` и `PaymentObject`.
- В **личном кабинете Т-Бизнеса** подключается касса **CloudKassir**, которая формирует чек по данным `Receipt` от Т-Банка. У CloudPayments (CloudKassir) находятся сведения о чеках в «Чеки и кассы» → «Чеки».
- **Не вызывать дополнительно `https://api.cloudpayments.ru/kkt/receipt` из webhook Т-Банка** при работающей связке эквайринг→CloudKassir: риск двойных чеков.
- При возвратах Т-Бизнес / CloudKassir поддерживает автоматическое оформление чека возврата в рамках интеграции, но **проверка данного случая на нашей кассе обязательна**.

## Ручная настройка, выполняет владелец доступа

1. Убедиться, что есть договор CloudKassir, зарегистрирована ККТ/ФН и заключён договор с ОФД. Сверить карточку регистрации, ИНН продавца, адрес расчёта `artemcarbon.ru`, ФФД **1.2**, версию ФН и кассовый статус.
2. В CloudPayments: «Сайты» → нужный сайт → скопировать **Public ID и пароль API**. Пароль не помещать в GitHub, тикеты, чат, репозиторий и скриншоты.
3. В **Т-Бизнесе, веб-кабинет (не мобильное приложение)**: «Интернет-эквайринг» → «Магазины» → наш интернет-магазин `artemcarbon.ru` → вкладка «Онлайн-касса» → CloudKassir → «К подключению» / «Добавить данные кассы». Ввести Public ID, пароль API и ФФД 1.2, сохранить.
4. Подтвердить с бухгалтером **налоговый режим**, **ставку НДС для каждого SKU**, предмет и способ расчёта. Сейчас `TBANK_TAXATION` и `TBANK_ITEM_TAX` берутся из `.env`, а `PaymentMethod` в коде равен `full_payment` для всех SKU. Это **не следует считать окончательно утверждённым**, особенно если физические товары доставляются позднее и при оплате имеет место предоплата. В зависимости от расчётов могут требоваться несколько чеков и/или особые реквизиты. Не менять значения наугад.
5. Нужные серверные переменные **на VDS, без публикации значений**: `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD`, `TBANK_TAXATION`, `TBANK_ITEM_TAX`, `TBANK_API_URL`, `PUBLIC_SITE_URL`, `API_PUBLIC_URL`. Ключи CloudKassir в нашем Node.js API не нужны: они указываются **в кабинете банка**.
6. В административной панели Artem Carbon «Параметры чека Т-Банка: заполнены» означает **только наличие конфигурации на сервере**. Оно не проверяет активацию кассы, связь с терминалом, тестовый/боевой режим и чеки в ФНС.

## Тестирование и запуск (два отдельных этапа)

**А. Проверка связки банка с кассой без публичного запуска сайта.**

- CloudPayments рекомендует небольшую **реальную оплату 5–10 ₽** в **боевом эквайринге Т-Банка**, при ещё тестовой CloudKassir. Карты CloudPayments для тестового эквайринга не подходят.
- Если доступна отдельная привязанная к той же кассе оплата по ссылке из Т-Бизнеса, её можно использовать для первичной проверки связки, **но это не заменяет проверку нашего сайта и /v2/Init**. Убедиться, что используется магазин/терминал, действительно привязанный к CloudKassir.
- Ожидаем: в ЛК CloudPayments «Чеки и кассы» → «Чеки» появляется **тестовый чек**, он приходит на указанный email. **Тестовый чек не отправляется в ФНС.**
- Нельзя запускать тестовую покупку без согласованных условий или считать успешный банковский платёж подтверждением фискализации.

**Б. Контрольный платёж через Artem Carbon.**

- Только после разрешения операторов, юридического согласования сайта и отдельного безопасного разрешения тестового приёма платежей.
- Для проверки нашего `/v2/Init` необходимо пройти реальный путь покупателя, проверить точное соответствие `Receipt`, факт платежа, email чека, запись чека в CloudPayments, выдачу номера и доступа к уроку.
- Текущий минимальный видеопродукт стоит 2000 ₽. **Не снижать его цену и не создавать фиктивные «номера участия» ради теста 5–10 ₽.** Для малой суммы нужен отдельно согласованный ограниченный сценарий тестового товара, не затрагивающий счётчик 9500, либо реальная покупка и корректный возврат с проверкой чека возврата.
- Сверить НДС, наименование, количество, сумму, `PaymentMethod`, `PaymentObject`, реквизиты продавца, ФФД, данные покупателя; проверить возврат, повторный webhook, ошибки кассы, пропавший чек.
- Положительный статус Т-Банка **не равен** подтверждённому фискальному чеку: если чек не найден, остановить открытие продаж и обратиться в поддержку.

**В. Перевод кассы в рабочий режим.**

- После успешной проверки отправить менеджеру CloudKassir письмо о готовности к полноценному запуску.
- Менеджер CloudKassir переводит кассу в **боевой** режим; только реальные чеки в нём передаются через ОФД в ФНС.
- Подтвердить активную ККТ, выдачу настоящего чека и возврата. Только после этого и закрытия других блокеров отдельно разрешать `PAYMENTS_ENABLED=true` на публичном сайте.

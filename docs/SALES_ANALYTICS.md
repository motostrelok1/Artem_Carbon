# PR: Аналитика оплат и покупателей

## Что реализовано
- В демо-админку добавлен раздел «Аналитика»: уникальные оплатившие покупатели, подтверждённые заказы, оплаченные видеоуроки, чистая выручка, график по дням, последние оплаченные заказы, фильтр сегодня / 7 дней / 30 дней / всё время.
- Пока серверное API недоступно, интерфейс показывает «—», а не нули и не фиктивные продажи.
- Подготовлена миграция базы `server/sql/001_sales.sql`.

## API-контракт
`GET /api/admin/analytics?period=day|week|month|all` — **только после серверной авторизации** с HttpOnly cookie, недоступно анонимным клиентам.

Форма ответа:
```json
{"uniquePaidCustomers":320,"paidOrders":410,"soldLessons":1250,"netRevenueKopecks":250000000,"dailyRevenue":[{"date":"2026-11-11","amountKopecks":200000}],"orders":[{"orderId":"uuid","paidAt":"2026-11-11","product":"video_lesson","quantity":1,"amountKopecks":200000}]}
```

Публичное API `GET /api/public/stats` возвращает лишь `{"soldLessons":N}` без персональных данных.

## Учет
- Только подтверждённый `CONFIRMED` от банка → `orders.status='paid'`.
- Вернувшиеся платежи исключаются из количества продаж и выручки.
- `uniquePaidCustomers`: число различных `customer_id` в оплаченных заказах.
- `soldLessons`: сумма `order_items.quantity` с `sku='video_lesson'` и статусом `paid`.
- Дневная выручка использует `paid_at`; возвраты учитываются как корректировки (полная политика частичных возвратов — отдельный этап).
- Публичный прогресс 9500 — только видеоуроки, а не физическая продукция.

## Безопасность и ввод в эксплуатацию
Текущий клиентский пароль `666666` — демонстрация, НЕ авторизация. Реальная аналитика не должна быть доступна через этот пароль без серверной защиты. До настройки `admin-api-base` и серверного login статистика недоступна.

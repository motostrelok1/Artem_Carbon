# PR #67 — Nginx: активное ограничение HTTP-флуда

**Статус:** отдельный PR, пока не слит. Автоматический деплой стартует при слиянии в `main` — на production не применять до успешного CI и проверки отката.

## Основание для включения

22.11.2026 пользователь проверил конфигурацию Nginx и API на VDS:
- `nginx -t` успешен, Nginx — `active`;
- `GET https://api.artemcarbon.ru/api/public/stats` возвращает HTTP 200;
- в журнале видны `req_limit=PASSED`, `DELAYED_DRY_RUN` и `REJECTED_DRY_RUN`, а `conn_limit=PASSED`;
- в последних 50 строках (41 запись) были 13 `PASSED`, 22 `DELAYED_DRY_RUN`, 6 `REJECTED_DRY_RUN`.

**Ограничения наблюдения:** проверка — искусственный короткий всплеск с одного IP, а не анализ боевого трафика под пиковыми нагрузками. Перевод в активный режим следует сопровождать наблюдением за покупателями и возвратом в dry-run при ложных срабатываниях.

## Какие правила включаются

| Запросы | Порог | Режим |
|---|---|---|
| `/api/` на `artemcarbon.ru` и `api.artemcarbon.ru` | 8 req/sec/IP, burst 20 | **Активный `limit_req`**; при превышении — HTTP 429 |
| `/api/admin/login` на обоих HTTPS-хостах | 5 req/min/IP, burst 3 | **Активный `limit_req`**, отдельная зона; при превышении — HTTP 429 |
| `/api/payments/tbank/notification` | Исключение из Nginx rate/conn limits | Без блокировки запросов от банка; Node.js проверяет подпись и платёж |
| `/health`, статический сайт и ACME | Без Nginx request/connection limits | Не меняются |
| `limit_conn ac_api_connections 20` | 20 соединений/IP | **Остаётся `limit_conn_dry_run on`**; отклонения по соединениям пока не включаем |

Внимание: `burst=20` с настройкой без `nodelay` позволяет откладывать часть превышающих базовую скорость запросов. В момент значительного всплеска возможна дополнительная задержка вплоть до нескольких секунд, а при исчерпании очереди — HTTP 429. У HTTP/2 учёт одновременных запросов имеет особенности. Длинные запросы и трафик покупателей за одним NAT могут давать ложные срабатывания.

Включение меняет только строку `limit_req_dry_run on;` на `off;` в двух обычных API и двух login locations. Параметры безопасности/проксирования, T-Bank, HTTPS, SSH, UFW и DNS не меняются. Изменения выполнены внутри `scripts/deploy-full-vds.sh`, который при каждом деплое пересоздаёт vhost.

## Проверка перед слиянием

1. CI workflow `nginx-protection-check.yml`: `bash -n`, тесты расположения/исключений и `nginx -t` с тестовым сертификатом — зелёные.
2. До деплоя: доступ в консоль VDS, команда возврата к dry-run, резервный доступ SSH, мониторинг и окно внедрения.
3. Не отправлять искусственные подписанные webhook банка на production. Проверку повторных уведомлений проводить в тестовой среде.

## Проверка сразу после деплоя

```bash
sudo nginx -t
sudo systemctl is-active nginx
curl -s -o /dev/null -w 'API HTTP: %{http_code}\n' https://api.artemcarbon.ru/api/public/stats
sudo tail -n 30 /var/log/nginx/artemcarbon-antiflood.log
```

Проверить браузерный сценарий 1–10 / 10 / 25 / 50 / 100, админский login/logout, API stats, `www` redirect, `/health`, отсутствие необычных 429 и 5xx. Не отправлять IP покупателей из логов в публичные сообщения.

После этого из небольшого согласованного тестового источника проверить контролируемое превышение API (не более 30 запросов) и убедиться, что появляются `req_limit=REJECTED` и HTTP 429 **без** `_DRY_RUN`. Обычные запросы должны возвращать HTTP 200. Не проводить длительное нагрузочное тестирование на production.

Для наблюдения за кодами и rate-limit статусами:

```bash
sudo tail -n 200 /var/log/nginx/artemcarbon-antiflood.log | \
  awk '{print $(NF-1), $NF, $(NF-4)}' | sort | uniq -c
```

Раздельно анализировать запросы от реальных покупателей за NAT. Цель — не допускать массовых ложных 429, потери заказов или ошибок авторизации. При росте 429, проблемах оплат или жалобах — немедленно вернуть режим наблюдения.

## Быстрый временный откат на сервере (без изменения SSH/UFW)

Сделать только в случае обнаруженного вреда от активного ограничителя. Команда возвращает `limit_req` в dry-run **во всех четырёх locations**, сохраняя саму конфигурацию, соединения и банковские исключения:

```bash
sudo cp -a /etc/nginx/sites-available/artemcarbon.ru \
  "/etc/nginx/sites-available/artemcarbon.ru.pre-antiflood-rollback.$(date +%Y%m%d%H%M%S)"
sudo sed -i 's/limit_req_dry_run off;/limit_req_dry_run on;/g' \
  /etc/nginx/sites-available/artemcarbon.ru
sudo nginx -t && sudo systemctl reload nginx
```

Если `nginx -t` не прошёл — восстановить скопированный файл и снова проверить конфигурацию до `reload`. **Ручное переключение временное:** последующий деплой из `main` снова запишет активные правила. Для постоянного отката требуется revert PR #67 или отдельный исправляющий PR.

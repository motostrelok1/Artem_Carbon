# Новый VDS ARTEMS CARBON — автоматизированная подготовка

Целевой сервер: Ubuntu 22.04.5 LTS, 195.209.222.219. Подтверждённые характеристики: 4 vCPU, 7.8 GiB RAM, 78 GiB disk. Часовой пояс Europe/Moscow; UFW разрешает SSH/HTTP/HTTPS; Swap 2 GiB настроен.

## Запуск

После установки/завершения текущей установки PostgreSQL 16, скопировать скрипт на сервер или получить его из этой ветки:

```bash
sudo bash scripts/bootstrap-vds.sh
```

Скрипт идемпотентный: проверяет Ubuntu 22.04, ставит Node.js 24, PostgreSQL 16, Nginx, Fail2ban и базовые утилиты; создаёт системного пользователя `artems-carbon` и каталоги; включает службы; открывает только SSH/HTTP/HTTPS в UFW.

## Что скрипт намеренно НЕ делает

- Не меняет SSH-конфигурацию и не отключает парольный вход.
- Не удаляет и не перезаписывает существующие Nginx-конфиги.
- Не открывает PostgreSQL наружу.
- Не создаёт пароль БД и не записывает секреты.
- Не копирует и не восстанавливает production-данные.
- Не запускает SQL-миграции.
- Не создаёт/не заменяет systemd unit приложения.
- Не меняет DNS, домены, SMTP, банковские ключи и сертификаты.
- Не включает платежи: `PAYMENTS_ENABLED=false` должно оставаться неизменным.

## После bootstrap — обязательные отдельные этапы

1. Проверить `pg_lsclusters`, `ss -lntp`, `systemctl status nginx postgresql fail2ban`.
2. Снять свежий backup со старого VDS и проверить архив/дамп.
3. Создать роль и БД с отдельным случайным паролем (не передавать пароль в чат и shell history).
4. Сверить список и порядок всех SQL-миграций с рабочей базой; восстановить данные, не генерировать номера заново.
5. Перенести приложение и admin UI из проверенной ветки/релиза, заполнить приватный `.env` с правами 0600.
6. Создать systemd unit после проверки фактических путей, пользователя и переменных.
7. Настроить Nginx только после получения домена заказчика и согласования API origin.
8. Проверить health, вход в админку, почту, тестовый эквайринг и восстановление backup.
9. Переключать DNS только после приёмки. Старый VDS держать включённым до подтверждения целостности данных и стабильной работы.

## Приёмочные команды

```bash
node -v
npm -v
psql --version
sudo pg_lsclusters
sudo systemctl is-active nginx postgresql fail2ban
sudo ufw status verbose
free -h
df -h
```

Ожидается Node.js 24.x, PostgreSQL 16.x, службы active, UFW active, PostgreSQL доступен только локально.

## Подготовка пустой базы (отдельный этап)

После размещения проверенного репозитория в `/opt/artems-carbon` и до запуска API можно выполнить:

```bash
sudo bash /opt/artems-carbon/scripts/prepare-database.sh
```

Скрипт проверяет наличие всех пяти миграций, создаёт роль `artems_app` и базу `artems_carbon`, применяет миграции 001–005 по порядку и создаёт приватный `server/.env` с автоматически сгенерированным паролем. Пароль не выводится в терминал; файл имеет права 0600. Если `.env` уже существует, скрипт останавливается и ничего не перезаписывает.

Это создаёт **пустую новую базу**. Не запускать до получения и проверки production backup, если целевая база уже содержит данные. Сам скрипт не восстанавливает старые заказы и номера.

## Доступ оператора к каталогу приложения

Bootstrap добавляет пользователя `ubuntu` в группу `artems-carbon`, чтобы он мог проходить в закрытый каталог приложения без изменения владельца сервиса. После изменения групп требуется новый SSH-сеанс. Служба приложения продолжает работать от отдельного системного пользователя `artems-carbon`.

## Развёртывание API

После базового bootstrap запустить от root:

```bash
curl -fsSL https://raw.githubusercontent.com/motostrelok1/Artem_Carbon/ops/new-vds-bootstrap/scripts/deploy-api.sh | sudo bash
```

Скрипт получает контролируемую ветку, размещает исходники в `/opt/artems-carbon/repo`, копирует API в `/opt/artems-carbon/server` (сохраняя существующий `.env`), устанавливает production dependencies, запускает тесты и создаёт systemd unit. Если приватного `.env` ещё нет, API не запускается.

Не применять `prepare-database.sh` до решения о переносе production-данных. Для чистого нового проекта он создаёт пустую схему; для миграции сначала нужен свежий dump со старого сервера и сверка состава данных. Платежи и email остаются выключенными.

Примечание по admin UI: `scripts/deploy-api.sh` размещает также каталог `admin/` в `/opt/artems-carbon/admin`. Это обязательная часть deployment: контрактные тесты API проверяют реальную HTML/JS-панель и безопасность её вывода. Если тесты сообщают `ENOENT /opt/artems-carbon/admin/...`, обновить скрипт из ветки и повторить deploy; не обходить и не отключать эти тесты.

## Безопасный backup старой production-БД

Перед переносом запустить на **старом** VDS (не на новом):

```bash
curl -fsSL https://raw.githubusercontent.com/motostrelok1/Artem_Carbon/ops/new-vds-bootstrap/scripts/backup-source-db.sh | sudo bash
```

Скрипт читает только `DATABASE_URL` из `/opt/artems-carbon/server/.env` (или использует экспортированную переменную), создаёт PostgreSQL custom dump в `/opt/backups/artems-carbon`, проверяет архив через `pg_restore --list`, записывает SHA-256 и оставляет исходную БД без изменений. Он не останавливает приложение и не удаляет backup. Переносить на новый VDS нужно и файл `.dump`, и соответствующий `.sha256`.

**Важно:** не запускать `prepare-database.sh` на новом VDS перед решением о восстановлении: он предназначен для пустой базы с миграциями, а полный production dump уже содержит схему и данные. Для восстановления используем отдельный сценарий, который откажется работать с непустой целевой БД.

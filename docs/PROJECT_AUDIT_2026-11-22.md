## Реальное состояние ключевых функций

### Действует и подтверждено

1. Сайт и API работают за Nginx/HTTPS, деплой через GitHub Actions.
2. Антифлуд API реально возвращал HTTP 429 при контролируемой нагрузке; `limit_conn` продолжает dry-run.
3. Уже работающий Fail2ban `sshd` на новом VDS сохранён без переустановки конфигурации из PR #70.
4. Мониторинг каждые пять минут (PR #71); в журнале 21:05–21:35 МСК 22.11.2026 — ноль активных проблем.
5. Отправка Email **мониторингом** (PR #72): тест дошёл до `motostrelok@yandex.ru`; временный SSH-ключ для переноса SMTP удалён.

### Есть в коде, но нужны испытания

1. Админка: login/logout, обзор, заказ/аналитика, каталог, очередь писем, системные настройки. Проверка каждой таблицы/SQL на живых данных отдельно не зафиксирована.
2. Номера: `assignLessonNumbers` выделяет номера из `lesson_number_pool` после `CONFIRMED`, через PostgreSQL advisory lock и транзакцию; имеет проверку исчерпания и идемпотентности назначения.
3. Webhook банка: код проверяет токен и условия подтверждения платежа, ставит заказ в статус paid и добавляет `email_outbox`; тестовый и боевой эквайринг ещё не доведены до окончания.
4. Каталог/checkout: UI и часть серверной проверки есть, но полный путь покупки и возврата денег нельзя считать готовым.

### Не подтверждено / требует реализации

- Предоплатное резервирование лимита 9500 и гарантированный отказ в продаже при отсутствии свободных номеров **до списания**. Текущий `assignLessonNumbers` вызывается после `CONFIRMED`: при исчерпании нужно ручное урегулирование уже принятой оплаты.
- Реальная отправка покупателю правильного количества номеров, ретраи, защита от повторного письма.
- Корректность частичных возвратов, полная сверка с банком, фискализация.
- Юридические документы и требования к акции/розыгрышу, обработке ПДн.
- Внешний uptime-монитор на `dvizh-school.ru`: документирован PR #73, не развёрнут.
- Защита от перегрузки канала/сетевого DDoS до Nginx (провайдер/CDN).
- Восстановление сайта, API, PostgreSQL и настроек после аварии с проверенным RTO/RPO.

## Проверка обращения с .env

В текущем `scripts/deploy-full-vds.sh` есть три важных участка:
- `cp -a "$ENV_FILE" "$ENV_FILE.deploy-backup.<timestamp>"` перед деплоем;
- `rsync -a --delete --exclude='.env' --exclude='.env.deploy-backup*' ...`, который не должен стирать существующий `.env`;
- локальный Python-блок, меняющий только `PUBLIC_SITE_URL`, `PUBLIC_BASE_PATH`, `API_PUBLIC_URL`.

В этом коде **нет удаления SMTP-параметров**. Исчезновение значений из нового `/opt/artems-carbon/server/.env` само по себе не доказывает, что их удалил деплой. На старом `driving-school-web` SMTP был сохранён; он перенесён в отдельный конфиг **мониторинга** на новом VDS. Не считать это автоматической настройкой писем покупателям.

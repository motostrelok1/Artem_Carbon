# ARTEMS CARBON — Т-Банк эквайринг / подготовка серверного API

Статус: **реальная оплата выключена**. Этот PR не является запуском эквайринга и не подтверждает юридическую допустимость розыгрыша. Выдачу номеров розыгрыша не реализуем до юридического согласования.

## Установка в тестовой среде

1. Node.js >=22, PostgreSQL, HTTPS reverse-proxy (Nginx). Сервер слушает **127.0.0.1:3002**; наружу нужно публиковать только HTTPS.
2. `cd server && npm install && npm test`.
3. Создать отдельную БД и применить `psql -v ON_ERROR_STOP=1 -f sql/001_sales.sql`.
4. Создать защищённый env из `.env.example` **за пределами Git**. Указать `DATABASE_URL`, `API_PUBLIC_URL`, `PUBLIC_SITE_URL`.
5. Для серверной авторизации создать длинный случайный `SESSION_SECRET`; пароля администратора хранить нельзя: `ADMIN_PASSWORD_HASH` — `salt:hex_scrypt`. Пример генерации на сервере (без передачи пароля в чат): `node -e 'const c=require("node:crypto");const s=c.randomBytes(16).toString("hex");const p=require("node:readline").createInterface({input:process.stdin,output:process.stdout});p.question("Admin password: ",v=>{console.log(s+":"+c.scryptSync(v,s,64).toString("hex"));p.close()})'`.
6. Добавить в публичный `index.html` meta `artems-api-base` и в `admin/index.html` meta `admin-api-base`, например `https://api.example.ru`, **только когда API размещён и проверен**.
7. Временно оставить `PAYMENTS_ENABLED=false`; счётчик и аналитика могут получать реальные подтверждённые тестовые записи, но платёжный переход будет недоступен.
8. Подключать тестовый терминал T-Банка и фискализацию только с согласованными реквизитами `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD`, `TBANK_TAXATION`, `TBANK_ITEM_TAX`.
9. Перед настоящим запуском — юридическая проверка схемы продажи видеоуроков и передачи автомобиля, настройки онлайн-кассы, оферта, данные о возвратах и правила резервирования лимита 9500.

## Методы

- `GET /health`: состояние API.
- `POST /api/orders`: ожидает `{email,items:[{sku,quantity}]}`, принимает строго один SKU из каталога, вычисляет цену на сервере. Возвращает `{orderId,paymentUrl}` после `Init`.
- `POST /api/payments/tbank/notification`: сверка `TerminalKey`, SHA-256 Token, `OrderId`, `PaymentId`, суммы. Только `Success=true,Status=CONFIRMED` делает заказ оплаченным. Возвращает банку `200 OK` и тело `OK`.
- `GET /api/public/stats`: общедоступное число подтверждённых и невозвратных уроков.
- `POST /api/admin/login` и `logout`: серверная аутентификация с HttpOnly Secure SameSite=None cookie.
- `GET /api/admin/analytics?period=day|week|month|all`: аналитика только для авторизованного администратора.

## Важные ограничения текущей реализации

- Нет платёжной формы ввода карты на нашем сайте: покупатель перенаправляется на `PaymentURL` банка.
- Нет гарантированного ограничения доступных уроков 9500 при конкурирующих оплатах. До запуска нужен механизм резервирования и сверки остатка.
- Нет схемы частичных возвратов и распределения их по позициям заказа. **Перед включением реальных платежей** необходим полноценный возвратный цикл и сверка с кабинетом Т-Банка.
- Нет обработчика выдачи видео/уникальных номеров; будет дополняться отдельно после согласования правил.
- Тестовый и рабочий терминалы не следует смешивать; API-конфигурация и секреты только на сервере.
- GitHub Pages и клиентский демо-пароль `666666` не защищают данные. После установки API админка использует серверный login.
- В браузерах с ограничением third-party cookies админка на GitHub Pages может не получить cookie отдельного API-домена. Для боевой админки разместите фронтенд и API на одном site/origin или используйте reverse-proxy на основном домене.
- Обработчик webhook рассчитан на **полные** возвраты, не поддерживает `PARTIAL_REFUNDED`; требуется доработка до production.
- Нужны тесты интеграции с банком, Nginx/HTTPS, резервные копии и rate limiting на уровне прокси.

## Проверка

- `npm test`: тест подписи токена, защиты от подмены суммы, базового payload Init.
- Уведомление с неверным токеном/суммой не засчитывается.
- `AUTHORIZED` не засчитывается, `CONFIRMED` засчитывается один раз, повтор не дублирует.
- При отключённом `PAYMENTS_ENABLED` нельзя создать настоящий платёж.
- Возврат заказа исключает его из публичного счётчика.
- Для webhooks Т-Банк ожидает HTTP 200 с точным телом `OK`.
